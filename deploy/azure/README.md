# Розгортання стенда в Azure

Інфраструктура демонстраційного стенда Slipstream: одна віртуальна машина,
на якій засобами `docker compose` працюють PostgreSQL, застосунок і зворотний
проксі Caddy з автоматичним сертифікатом Let's Encrypt.

## Склад і вартість

Ціни взято з прайсового інтерфейсу Azure для регіону Poland Central.

| Ресурс | Вибір | USD/міс |
|---|---|---:|
| Віртуальна машина | `Standard_B1s` — 1 vCPU, 1 ГіБ, Ubuntu 24.04 LTS | 8,76 |
| Диск операційної системи | StandardSSD `E4`, 32 ГіБ | 2,40 |
| Публічна адреса | Standard, статична IPv4 | 3,65 |
| Мережа, підмережа, група безпеки, інтерфейс | — | 0 |
| **Разом** | | **14,81** |

Фактично розгорнуто `Standard_B2ats_v2` (2 vCPU, 1 ГіБ): `B1s` під час розгортання був
недоступний у регіоні. Ціни в таблиці стосуються початкового вибору.

Кредиту студентської підписки в 100 USD вистачає приблизно на 6,5 місяця
безперервної роботи. Якщо зупиняти обчислення між демонстраціями, лишається
плата лише за диск і адресу — близько 6 USD на місяць.

## Чому саме так

**`Standard_B1s`, а не `B1ms`.** Старша машина коштує 20,22 замість 8,76,
тобто кредит згорів би за 3,8 місяця замість 6,5. Ризик меншої машини —
одного гігабайта пам'яті може забракнути на перенавчання моделей. Його
закрито файлом підкачки на 2 ГіБ і можливістю збільшити машину однією
командою `az vm resize` без перестворення.

**Диск SSD, а не HDD.** Різниця 0,86 USD на місяць, але застосунок працює з
базою даних, і на механічному диску демонстрація помітно гальмувала б.

**Без керованої бази даних.** Azure Database for PostgreSQL коштує дорожче за
всю іншу інфраструктуру разом. Для стенда PostgreSQL у контейнері достатній.

**Локальний файл стану Terraform.** Віддалене сховище стану потребує окремого
облікового запису зберігання, контейнера та механізму блокування. Для проєкту
з одним виконавцем це надлишок.

## Іменування

Схема Microsoft Cloud Adoption Framework: `<тип>-<навантаження>-<середовище>-<регіон>`.

```
rg-slipstream-demo-plc        група ресурсів
vnet-slipstream-demo-plc      віртуальна мережа
snet-app-demo-plc             підмережа
nsg-slipstream-demo-plc       група безпеки мережі
pip-slipstream-demo-plc       публічна адреса
nic-slipstream-demo-plc       мережевий інтерфейс
vm-slipstream-demo-plc        віртуальна машина
osdisk-slipstream-demo-plc    диск операційної системи
```

## Порядок розгортання

```bash
# 1. вхід саме тим акаунтом, на якому студентська підписка
export AZURE_CONFIG_DIR=~/.azure-student
az login --use-device-code

# 2. параметри
cp example.tfvars terraform.tfvars
#    subscription_id  — ідентифікатор студентської підписки
#    allowed_ssh_cidr — ваша публічна адреса з маскою /32

# 3. розгортання
terraform init
terraform plan
terraform apply
```

Після `apply` виводяться доменне ім'я, публічна адреса й команда підключення.

## Доступ

Система доступна за іменем **https://slipstream-ci.duckdns.org**; ім'я, видане
платформою, перенаправляє на нього (див. `../README.md`, розділ «Доменне ім'я»).

Порт 22 відкрито **лише з адреси, зазначеної в `allowed_ssh_cidr`**. Паролів на
машині немає: автентифікація виключно за ключем SSH. Порти 80 і 443 відкриті
назовні, решта закрита і групою безпеки Azure, і мережевим екраном `ufw` на
самій машині.

Якщо провайдер змінить вашу адресу, оновіть `allowed_ssh_cidr` і виконайте
`terraform apply` — доступ відновиться.

## Економія кредиту

```bash
# зупинити обчислення між демонстраціями (диск і адреса лишаються)
az vm deallocate -g rg-slipstream-demo-plc -n vm-slipstream-demo-plc
az vm start      -g rg-slipstream-demo-plc -n vm-slipstream-demo-plc

# збільшити машину, якщо забракне пам'яті
az vm resize -g rg-slipstream-demo-plc -n vm-slipstream-demo-plc --size Standard_B1ms

# прибрати все
terraform destroy
```

## Що не потрапляє в репозиторій

`terraform.tfstate` містить відкритим текстом усе, що Terraform знає про
ресурси, зокрема чутливі значення, тому його внесено до `.gitignore` разом
із `terraform.tfvars` і каталогом `.terraform/`.
